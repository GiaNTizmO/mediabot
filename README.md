# mediabot

Telegram-бот для скачивания видео и музыки с **YouTube, YouTube Shorts, YouTube Music, TikTok и Instagram**.
Вы присылаете ссылку, бот показывает превью и варианты (качество видео или MP3), а потом присылает выбранный файл.

Стек: aiogram 3, yt-dlp, ffmpeg.

## Возможности
- Превью с обложкой, названием, автором и длительностью
- Варианты качества (до 1080p) с примерным размером; ⚠️ помечает файлы больше лимита
- Любое видео можно скачать как музыку: **MP3** или **M4A** (оригинальный звук без перекодирования)
- **Обложка аудио** — превью ролика, обрезанное до квадрата; вшивается в файл и видна в Telegram и любом плеере
- Теги: название, исполнитель, альбом и год (для YouTube Music и официальных треков YouTube)
- **YouTube Music**: для таких ссылок аудиоварианты стоят первыми, файл называется «Исполнитель - Трек»
- **Выбор звуковой дорожки**: если у ролика несколько озвучек (разные языки), после выбора качества бот предлагает выбрать одну дорожку. Оригинал помечен, русская озвучка идёт следующей. Работает и для видео, и для MP3/M4A
- **Файлы называются как ролик** (для всех источников): запрещённые символы и хэштеги TikTok/Instagram убираются
- Прогресс загрузки (процент, скорость, ETA) и кнопка **«Отмена»**
- Правильные пропорции и превью для вертикальных видео (Shorts/TikTok/Reels)
- Предпочтение H.264/AAC, чтобы видео проигрывалось во всех клиентах Telegram
- **Файлы не хранятся на сервере**: видео лежит на диске только между загрузкой и отправкой и удаляется сразу после отправки (а также при ошибке или отмене). При старте бот подчищает остатки после возможного падения и заранее проверяет, хватит ли свободного места.
- **Кэш file_id** (SQLite, несколько КБ): повторный запрос того же видео отправляется мгновенно — сам файл хранит Telegram, не ваш сервер
- Очередь: ограничение одновременных загрузок, одна загрузка на пользователя
- Работа в группах: бот реагирует только на ссылки, а кнопки нажимает только автор запроса
- Понятные сообщения об ошибках (приватное видео, нужна авторизация, недоступно…)
- Опционально: локальный Bot API для файлов до 2 ГБ, белый список пользователей, cookies

## Запуск через Docker (рекомендуется)
```bash
cp .env.example .env      # впишите BOT_TOKEN от @BotFather
docker compose up -d --build
```
Файлы до 2 ГБ — см. раздел «Большие файлы (до 2 ГБ)» ниже.

## Запуск без Docker
Нужны Python 3.10+, `ffmpeg` и [deno](https://deno.com) (для YouTube требуется yt-dlp).
```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m bot
```

## Настройки (.env)
| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | токен бота (обязательно) |
| `MAX_FILE_MB` | лимит размера файла: до 50 (облачный API) или до 2000 (локальный Bot API) |
| `LOCAL_API_URL` | адрес локального telegram-bot-api |
| `ALLOWED_USERS` | user id через запятую; пусто означает доступ для всех |
| `COOKIES_FILE` | cookies.txt для Instagram/YouTube с ограничениями |
| `MAX_CONCURRENT` | одновременных загрузок (по умолчанию 3) |
| `DATA_DIR` | папка для кэша file_id |
| `TEMP_DIR` | где держать файл на время загрузки (по умолчанию системный /tmp) |

## Советы
- Instagram часто требует авторизацию: экспортируйте cookies.txt расширением «Get cookies.txt LOCALLY».
- Сайты меняются, и yt-dlp периодически ломается. Обновление: `pip install -U "yt-dlp[default]"` или `docker compose build --pull`.

## Большие файлы (до 2 ГБ)
Облачный Bot API позволяет боту отправлять файлы только до **50 МБ**. Чтобы поднять лимит до **2000 МБ**,
рядом с ботом запускается локальный Bot API сервер (уже описан в `docker-compose.yml`).

1. Получите `api_id` и `api_hash`: войдите на https://my.telegram.org → **API development tools** →
   создайте приложение (название и описание любые).
2. Добавьте в `.env`:
   ```
   COMPOSE_PROFILES=pot,local-api     # pot — если включали PO-токены, иначе просто local-api
   LOCAL_API_URL=http://telegram-bot-api:8081
   MAX_FILE_MB=2000
   TELEGRAM_API_ID=1234567
   TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
   ```
3. `docker compose up -d --build`

При первом запуске бот сам выйдет из облачного Bot API (`logOut`, так требует Telegram) — в логе будет
«бот вышел из облачного Bot API». Готовый файл сервер берёт прямо с общего диска (`file://`), поэтому второй
копии не появляется, а сам файл, как и раньше, удаляется сразу после отправки.

**Место на диске:** во время загрузки нужно примерно 2,2× от размера файла (видео и звук + склейка),
т.е. для файла 2 ГБ — около 4,5 ГБ свободного места. Если места не хватает, бот заранее предупредит.

**Вернуться на облачный API:** уберите `LOCAL_API_URL` и `local-api` из `COMPOSE_PROFILES`, верните
`MAX_FILE_MB=50`, удалите файл `data/cloud_logged_out` и подождите 10 минут после перехода на локальный сервер
(ограничение Telegram).

## Авторизация (cookies.txt)
Нужна, если бот отвечает «требует вход» или «подтвердить, что вы не бот»:
- **YouTube** часто требует подтверждения «я не бот» с серверных (датацентровых) IP;
- **Instagram** без входа отдаёт мало контента и быстро упирается в лимиты.

Используйте **второстепенный аккаунт**: сайты могут ограничить аккаунт, который качает через yt-dlp.
Cookies дают полный доступ к аккаунту, поэтому никому их не передавайте и не коммитьте (`cookies.txt` уже в `.gitignore`).

### 1. Экспорт cookies
Установите расширение **Get cookies.txt LOCALLY** (Chrome) или **cookies.txt** (Firefox).

**YouTube** (по рекомендации yt-dlp, иначе cookies быстро «протухают»):
1. Откройте окно **инкогнито** и войдите в YouTube.
2. В той же вкладке перейдите на `https://www.youtube.com/robots.txt`.
3. Экспортируйте cookies для `youtube.com` и **закройте окно инкогнито, не выходя из аккаунта**.

**Instagram**: войдите на instagram.com, экспортируйте cookies для `instagram.com`.

Нужны оба сайта? Склейте файлы в один `cookies.txt`, оставив строку-заголовок `# Netscape HTTP Cookie File` один раз.
Не экспортируйте «все cookies браузера»: туда попадут сессии почты, банков и т.д.

### 2. Подключение к боту
**Docker:** положите `cookies.txt` рядом с `docker-compose.yml`, раскомментируйте строку
`- ./cookies.txt:/app/cookies.txt:ro`, в `.env` укажите `COOKIES_FILE=/app/cookies.txt` и выполните `docker compose up -d`.

**Без Docker:** в `.env` укажите `COOKIES_FILE=/полный/путь/cookies.txt` и перезапустите бота.

Бот работает с копией файла: оригинал не изменяется, и его можно смонтировать только для чтения.

### 3. Проверка
При старте бот пишет в лог, что нашёл в cookies (`docker compose logs bot | grep cookies`):
```
cookies: YouTube: вход найден (21 cookie, истекают через 395 дн.)
```
Проверить файл вручную: `docker compose exec bot python -m bot.cookies_check /app/cookies.txt`.
Если там «нет cookie входа», значит, при экспорте вы не были залогинены, и файл нужно экспортировать заново.

### 4. PO-токены для YouTube (если «я не бот» не уходит)
На серверных IP YouTube строже. Плагин [bgutil-ytdlp-pot-provider](https://github.com/Brainicism/bgutil-ytdlp-pot-provider)
уже установлен в бота, ему нужен только сервер-генератор токенов. Добавьте в `.env`:
```
COMPOSE_PROFILES=pot
POT_PROVIDER_URL=http://pot-provider:4416
```
и выполните `docker compose up -d --build`. PO-токены работают **вместе** с cookies, а не вместо них.
Если не помогло и это, остаётся прокси с «домашним» IP.

Подробная причина любой ошибки пишется в лог: `docker compose logs bot`.

### 5. Подробная диагностика
```bash
docker compose exec bot python -m bot.diagnose "https://youtu.be/VIDEO_ID"
```
Проверяет cookies и токен-сервер, затем запускает yt-dlp в подробном режиме с настройками бота.
Важные строки: `Found YouTube account cookies` (yt-dlp принял вход) и `PO Token Providers: bgutil:http…`.
Значения cookie в вывод не попадают.
